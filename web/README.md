# web/ — 求职总览页

总览页的界面就在这里：**antd 6 + React 19 + TypeScript**。

## 两种打开方式，同一套界面

| | 怎么开 | 适合 |
|---|---|---|
| **起服务** | `/job-dashboard`（跑 `python tools/serve.py`） | 用户就走这一条 |
| **开发** | `npm run dev`（要另起 serve.py） | 改界面，有热更新 |

**两者渲染的是同一份代码。**

> **还曾有第三种：单文件快照**（`bundle_web.py` 把 JS/CSS/数据全部内联成一个
> 双击就能开的 HTML）。**删了**——不是因为它不能用，是因为它**残**：状态按钮
> 全部走 `hasServer()` 判断，没有服务时整排不渲染，于是一个岗上只剩「不投这个岗」
> 这一个纯前端的本地标记——**能标不投，标不了已投**。用户点完以为记上了，
> 刷新就没了。一个只能记坏消息的面板比没有面板更坏。

> **曾经有两套面板。** `tools/build_dashboard.py` 自己吐一整页 HTML，与这里并存，
> 各有一份布局、一份文案、一份 CSS。于是「同一条规则只修一侧」反复发生——判词的
> 「粗筛：」前缀、`optional` 与 `silent_fail` 两个字段、CSS 变量名、
> 「材料就绪」的计数口径，都飘过。那 738 行渲染已经删掉，`build_dashboard.py`
> 现在只剩解析与计算，两条路读的都是它。

第一次跑要构建一次前端：

```bash
cd web && npm install && npm run build
```

只需要一次。之后数据变了直接跑 `/job-dashboard` 或 `python tools/serve.py`。

## 跑起来

```bash
cd web
npm install
npm run dev      # http://localhost:5173
npm run build    # 产物在 dist/
npm run typecheck
```

## 接你自己的真实数据

```bash
python tools/export_web_data.py          # 导出到 users/<活动用户>/job_scraper/dashboard/（已 gitignore）
cd web && npm run build && cd ..
python tools/serve.py                    # 起本地服务，自动打开浏览器
```

## 页面上能直接做的事

### 顶部快捷卡片

- **招聘网站**：监控猎聘、BOSS直聘、智联招聘、前程无忧四家渠道的抓取状态与简历刷新时间。
  > **为什么 BOSS直聘和前程无忧标了「需开 APP 刷新」？**
  > 这两家在网页端不提供「刷新简历」按钮（只在移动端 APP 开放）。总览页会在此醒目提示并附带操作指引，防止求职者误以为网页端能自动刷新而在不知情的情况下简历沉底、错失 HR 主动检索。
- **岗位类型偏好**：一键切换外包、驻场、未公开公司等岗位类型的显示与过滤，配合按公司名、职位关键词筛选，快速保持视野聚焦。
- **要装的工具**：实时查看本机环境（Python、Node、Typst 等）就绪状态。
- **命令手册**：内置从填资料、搜岗位、评分、出材料到记录结果的常用命令手册，无需翻阅文档即可速查。

### 岗位详情展开与投递操作

每个岗展开后，「这个岗」那一行有状态按钮，按**当前状态**给下一步
（还没投 → 我投了；已投 → 约面了 / 挂了 / 没下文；面试中 → 拿到 offer；
offer → 入职了 / 我拒了），而不是摆一个八选一的下拉框。旁边是「不投这个岗」。
**两者都直接写回盘上，可撤销。**

`serve.py` 只绑 `127.0.0.1`，每次启动生成一次性 token 注入页面，写操作必须带上它
（否则你打开的任何网站都能往 `localhost:29029` 发 POST 改你的数据）。它**不接大模型**：
这里每个操作都是改一个字段，不需要判断力。真要模型的活（找职位、深评、写简历）
继续在 Claude Code 里跑——那边有浏览器扩展、走你的订阅，两样都是这个服务给不了的。

**为什么必须起服务、不能双击 `dist/index.html`**：`npm run build` 出来的是
「静态文件 + ES module」，Chrome 不允许 `file://` 加载 ES module，
`fetch("data.json")` 同样被拦。

改界面时用 `npm run dev`（有热更新）。

导出器做两件事：把 `seen_jobs.json` 与 `documents/applications/*/` 里的评估、话术
读出来写成 `public/data.json`，并**把真实的 resume.pdf 复制进 `public/pdf/`**
——这样「打开定制简历 PDF」那个按钮才真的能打开。输出目录整体 gitignore。

它复用 `build_dashboard.py` 的解析器（`find_applications`），不写第二套：投递目录的
职位链接有优先级（`outreach.md` 的「职位链接：」优先，`posting.md` 兜底），
自己再写一遍必然飘。

## 没导出时是虚构演示数据，页面会自己说出来

读不到 `data.json` 就回退 `src/data/sample.ts`，同时在页头挂一条醒目的
**「演示数据（虚构）· 链接与简历 PDF 都是假的」**。

这条标记是必须的。第一版没有它，于是虚构数据长得跟真的一样：职位链接点了打不开、
「打开定制简历 PDF」指向一个不存在的文件——按钮看着能用其实是死的，比没有按钮更糟。
**演示数据必须自己承认自己是演示数据。**

演示数据全是编的，但**边界情况是真的**：薪资三种口径、公司名未公开、硬性条件
「还没查到」、某项没有分数、不满足硬性条件——版面撑不撑得住取决于这些形状。
真实评估内容会带出候选人的个人信息（不会哪些技术、学历口径、语言水平、薪资底线），
那些属于 `profile/`（已 gitignore），不进公开仓库。

## 缺的字段不占位

平台没给薪资/地点/年限是常事（列表页给什么就有什么）。这种字段**空着就不渲染**，
不印「未标年限」——那是把「我们没抓到」说成一条信息，满屏都是噪音。
同理某一项没有分数时写「这项没打分」，不画成 0 分。

## 界面上为什么这么写

下面这些取向都是从这个工具本身读出来的，不是随手选的风格。
（这句原来写「三条」，而下面早就不止三条了——**数字写死在文字里，加一条就飘一次**。）

1. **四态方章，不是开关。** 硬性条件有四种状态：满足（过）、不满足（否）、还没查到
   （疑）、不涉及（无）。「还没查到」既不算满足也不算不满足，**永远不能被折叠成满足**
   ——所以在 `types.ts` 里它是一等成员，不用 `boolean | null` 那种会诱人写 `?? false`
   的形状。四态靠**形制**区分（实心 / 斜纹 / 空心 / 虚线）而不只靠颜色，色盲可辨，
   缩到 17px 颜色失效时也仍然可辨。
2. **行动优先，参数不上屏。** 点进一个岗，最先看到的是怎么投：职位原始链接、
   **「复制开场白」**（整页最常按的一下，所以它是这块里唯一带字的按钮，不是一个
   14px 的灰图标）、定制简历——没出材料就给可复制的 `/job-apply` 命令。
   打分依据以人话列出（对口的地方 / 要掂量的地方），**权重百分比不显示**：
   「占 30%」是打分器的内部参数，对用户没有行动意义。名单顶部直接标出「推荐先投」。

   > **这条规矩光写在这儿不算数。** 它在这份 README 和 `JobReadout.tsx` 顶上都写着
   > 理由，却**没有一处是可执行的**——2026-08-18 实测导出的 `data.json` 里 176 条
   > 打分依据原样印着「专业能力 88 × 0.6 + 业务领域 65 × 0.4 + 加分项 +2」。
   > 现在落在 `export_web_data.strip_weights`：显示层把权重整段拿掉，只留两个分
   > （「专业能力 88 · 行业经验 65」）。上游怎么写归 `workflows/job-apply.md` 管，
   > 但**存量的两千多条评估不会为一条新规矩重跑一遍**，所以最后一道必须在这里。
   > `tests/test_display_wording.py` 的 `TheOtherPathFromEvaluationToTheScreen` 盯着。
3. **一个总分不够，要能看出这个分是谁撑起来的。** 职位到 84 个之后，20 个岗挤在
   58-78 分，总分已经分不出高下。所以名单里并排显示三个数：

   | 分 | 技能 | 年包 | 读法 |
   |---|---|---|---|
   | 74 | 61 | 72-126万 | 钱最好，活一般 |
   | 66 | 82 | 36-48万 | 活最对口，钱最少 |

   技能高于总分 → 青色（活对口、被薪资等条件拖下来）；低于 → 琥珀（分是薪资撑的）。
   年包是**折算好**的：原始串有 `25-35k·20薪`、`40-70k`、`3.5-5万`、`10-15万/年`
   四种口径，跨岗心算不是用户该干的事。
4. **标记长在职位后面，不堆在分数格里。** 「已投」「这家投过」「读过 JD」
   「材料就绪」说的都是这个岗的事。它们原来竖着塞在 88px 宽的分数格里，一行能堆
   四层，行高被撑到 130px（24 行 ≈ 3100px 的滚动），而右边职位那一列在 1440px 下
   有五百多像素空着。挪到公司/地点后面横排之后行高**统一 76px**，参差也一并没了。

5. **待核实的信息与打分物理分开。** 平台信息自相矛盾、公司名查不到，这些是信息
   可信度问题，不是岗位的缺点，所以不扣分。混排会让人以为查不到也会被扣分。

6. **详情长在它自己那一行下面，同时只开一个。** 点任意一行就地展开，不把人甩到
   表格外一千像素处——点第 15 行还要滚下去看详情、回来又找不到刚才那行，
   是最容易丢失上下文的做法。展开区与所属行共用一条左侧强调边、中间没有缝，
   看起来就属于上面那一行。进页面时**不预展开任何一行**：预展开第一行会把下面
   18 行推出屏幕，反而看不到名单。
7. **没有数据时不许渲染成结论。** 只过了粗筛的岗没有硬门核对、没有能力边界比对，
   这时**绝不能**渲染那四个区块——它们的空状态文案会把「没有数据」说成
   「这些条件都核对过了，没有要问的」，用户会以为硬门验过了。改为一句实话 +
   可复制的 `/job-apply`。

8. **空的区块整块不渲染，而不是留一个带标题的空盒子。** 上一版是「盒子留着、
   副标题改一句话」（「这个岗没有」），实测下来那不叫说出结论：左边一行小字下面
   60px 空白，右边更糟——`quality` 为空时一条守卫都没有，照样渲染出标题、一个
   「不算进分数」的标签、一个空列表，外加一句解释屏幕上不存在的东西的脚注。
   「没有对不上的地方」确实是个结论，但它值一行，不值两个框。

9. **长到翻不动的名单要截断，并说清截了什么。** 「不投的岗位」曾把全部 2086 行
   一次铺出来：页高 164080px、DOM 一万六千个节点，展开那一下浏览器直接卡死。
   而这份名单里真有事可做的只有能放回的那 90 个，其余是「硬性条件没过」的存档，
   翻不动也没有按钮可按。现在按「你自己标的 → 已下线 / 规则判的 → 其余」排序取前
   60 条，剩下的用一句话交代是什么、有多少。**不做「全部展开」**——点开就是同一次
   卡死，把炸弹换个位置放不算修好。

## 措辞规则

界面上一律用求职者自己会说的话。`workflows/` 里的框架词（硬门、能力边界、四维）是
给 AI 看的，不往界面上搬——对照表见仓库根 `AGENTS.md`「给用户看的措辞」。
排版上跟着一条：**等宽字体加大字距只适用于拉丁文**，中文套上去会被拉成散字，
中英混排还会在接缝处炸出大间隙。等宽只留给纯数字。

> **加大字距连纯数字也别加。** `.mono-label` 原来带 0.17em——而全仓库 13 处用它的
> 地方**全是纯数字**，一个拉丁标签都没有。摊在数字上就是把一个数拆成几个：屏幕上
> 出现「投出去超过 1 0 天」「6 6」「2 0 条」「8 2」。而且 `.sec-count` 和
> `.rail-step` 早就各自写了一遍 `letter-spacing: 0` 把它抵消掉——**同一件事在三处
> 各修一次，说明默认值选错了**。现在类里就是 0，规则本身留着（中文不许进这个类）。

另有一条同源的：**换词会自己造出中文之间的空格**。`plain()` 把
「不判 FAIL」换成「不判 不满足」时，那个原本给拉丁词留的空格夹在了两个汉字中间；
折行拼接也一样（「没有公司名， 本轮无法独立核实」，实测 21 条）。所以 `plain()`
末尾统一收一次中日韩之间的空格，中英之间的照留。

## antd 在这里的角色

antd 组件**只当底座**，负责交互逻辑与可达性（Table 的排序与键盘导航、Tooltip 的
aria 关联、Collapse 的展开语义）。视觉全部由 `src/theme/tokens.ts` 的 token 与
`src/theme/cockpit.css` 的 CSS variables 接管，目标是让人看不出这是 antd 默认观感。

antd 6 起 CSS variables 主题**默认开启且不可关**（`cssVar` 只剩 prefix / key 两个配置
项，传 `true` 会 TS2559）。`cockpit.css` 直接引用 `--ant-*` 变量，正是靠这一点；
同时关掉 `hashed`，类名稳定，覆盖选择器才写得出来。

哪些不用 antd，以及为什么：

- **方章不用 Tag / Badge**：Tag 是「标签」语义（可增删的属性），而这里是**判定**
  ——一次性、有权威、不可自行摘掉。方章是这个语义的正确形制。
- **匹配理由不用图表**：曾经做过一条「段宽 = 权重、高度 = 得分」的权重带，后来撤了
  ——它展示的是打分器怎么算，而用户要的是投不投、为什么、怎么投。理由直接用文字列出。

总览快照与 PDF 按用户保存在 job_scraper/dashboard/ 下，由本地服务提供。Vite 禁用 public 目录，旧的 public 文件不会进入构建或开发静态资源。
