# /job-user —— 看现在是谁在用、切换 / 新建 / 删除用户

多人共用一份 clone 时，每个人的数据在 `users/<名>/`，当前活动用户记录在仓库根
`.active_user`。本命令管理活动用户。**命名空间隔离，非加密**——同一操作系统账号下
数据互相可读，真要保密请用不同账号或各自 clone。

## 解析用户输入

- **无参** → 列出 `users/` 下所有用户，标出 `.active_user` 指向的活动用户；若 `users/`
  为空或 `.active_user` 未设，提示跑 `/job-setup` 新建首个用户。
- **`.active_user` 有内容，但 `users/<它>/` 不存在** → **指针坏了。这正是本命令
  存在的理由**：先说清它指着谁、盘上实际有谁，再给**一条**命令。

  ```bash
  python tools/doctor.py      # 三种情形该给哪条命令，它算得出来
  ```

  哪一条由自检给，**这里不复述那张分支表**（正本是 `tools/doctor.py` 的
  `next_step`：有已建档的用户 → 切过去；有目录但都没建档 → `--new`；
  一个都没有 → `--new`）。没有 Python 时自己判：`users/` 下有已建档的用户就
  `/job-user <那个名字>`，一个都没有就 `/job-setup`。

  > **这一支原来整个不在。** 而全仓的工具在这个状态下印的都是
  > 「跑 `/job-user` 看看有哪些用户」（`_cli.pick_user` 的报错原话，
  > 本文件「规则 1」里就引着它）—— 用户照着敲过来，**这份文档没有一句话
  > 告诉执行者该怎么办**：上面那条无参分支只认「`users/` 为空或未设」，
  > 指针指着一个不存在的目录，两种都不是。一个把人指过来、却接不住的闭环。
  >
  > `AGENTS.md`「会话开始」那一节点名的正是这件事：「`.active_user` 指向的
  > 目录不存在 → 引导 `/job-user`——**那是指针坏了，`/job-setup` 修不了**
  > （它只会再建一个新用户，原来那份数据仍然找不到）」。
  > 规则在总纲里立着，接活的这条命令没写。2026-09-02 通读时发现。
- **`<名>`** → 切换：校验 `users/<名>/` 存在。存在则把 `<名>` 写入 `.active_user`
  （覆盖，单行、无换行），**然后跑 `python tools/export_web_data.py`**，再回复
  「已切换到 <名>」。不存在则列出可用用户并提示 `/job-user --new <名>` 新建。

  > **切换后必须重导面板数据。** `web/public/data.json` 是按活动用户导出的快照；
  > 只改指针不重导，面板展示的还是**上一个人**的职位、分数与投递记录——张三打开
  > 总览页看到李四投了哪几家。命名空间隔离的仓库里，这不只是数据过时，是把别人的
  > 求职数据端给了错的人。重导是机械步骤，不问。
- **`--new <名>`** → 新建：转交 `/job-setup`（`/job-setup` 的新建流程会脚手架 `users/<名>/`
  并写 `.active_user`）。不要在此重复实现建目录逻辑。
- **`--remove <名>`** → 删除整个 `users/<名>/`。见下节。

## 删除用户

这是本仓库破坏性最大的操作：一个用户目录里有他全部的职位、评分、投递记录、定制简历
与求职信。**删除前必须先让他看见自己要放弃什么。**

### 第一步：列出会失去的东西

**四个数用工具算，不要手数**（自检认 `--user`，报的就是这四项）：

```bash
python tools/doctor.py --user "<名>"    # 已抓 N 个职位 · 已评 N · 已出材料 N 份 · 投递记录 N 条
```

> **同一条规矩在 `job-outcome.md` 上已经立过**：「该催哪几个 —— 用工具算，
> 不要手算」，理由是「这几条规则错了都是静默的」。而这里的静默错法更贵：
> 数少报了，他是**按一个偏小的数点的头**。

**目录里有什么，照 `AGENTS.md`「活动用户与多用户」那张枚举走** ——
那是这个仓库唯一的解析来源，`tests/test_multiuser_paths.py` 盯着它的完整性。
**别在这里手写第三份清单**：`job-reset.md` 已经有一份（它「不在本次重置范围内」
那一节），两份迟早各长各的。

照下面报（不存在的项不必提）：

> **要删除的是「<名>」，里面有：**
> - 职位 N 个、已评 N 个（`job_scraper/`，含抓过的 JD 正文与备份）
> - 投递记录 N 条（`job_search_tracker.csv`）
> - 投递材料 N 份（`documents/applications/`，每份含评估、开场白、简历 PDF）
> - 资料四件（`profile/`：经历、行为特质、面试 STAR、搜索词）
> - 简历与求职信源文件及已生成的 PDF（`resume/`、`cover_letter/`）
> - **学习计划**（`upskill/`）、**简历审核与总览页快照**（`reports/`）、
>   邮件同步状态（`gmail_sync/`）、你选的模板（`templates/active-*.md`）
>
> **删掉之后无法恢复**，也不进版本库（`users/` 已 gitignore，没有历史可回滚）。

> ⚠️ **最后那一行原来整个不在清单里。** 而 `job-reset.md` 恰恰把这条命令
> 写成了清掉它们的推荐做法（「要连这些一起清掉，最干净的做法是……用 `/job-user`
> 删除该用户」）——**它指过去的命令，不列它指过去要清的东西**。
> 用户读到的是「删掉职位和投递记录」，实际连简历审核报告和学习计划一起没了。

### 第二步：确认

> 确认删除请回复 **`删除 <名>`**，回复别的都算取消。

⚠️ **不要只让他重复一遍 `<名>`。** 名字他刚在命令里打过，复制粘贴就过了——
而这一步的破坏性比 `/job-reset` 大得多（`/job-reset profile` 只清 4 个 profile 文件，
这里是整个用户目录）。`/job-reset` 尚且要求敲一个**没打过的**词（`确认重置`），
删用户的确认强度不该更弱。带上 `<名>` 是为了防删错人，`删除` 二字是为了防手滑。

### 第三步：执行，并处理指针

- **删的不是当前活动用户** → 直接删目录，`.active_user` 不动。
- **删的就是当前活动用户，但还有别的用户** → 先把 `.active_user` 切到另一个存在的
  用户（告诉他切到了谁），再删目录。**不要让他自己先跑一次 `/job-user <其他>`**——
  那是把工具的实现细节推给用户。
- **删的是唯一的用户** → 照删，并把 `.active_user` **清空**（写入空文件或删除该文件），
  然后告诉他：「已删除。跑 `/job-setup` 重新开始。」

> ⚠️ **「唯一的用户」这条必须支持，不能拒绝。** 原来写的是「不允许删除当前活动用户
> （先 `/job-user <其他>` 切走）」——而 `/job-user <名>` 要求目标目录存在，**只有一个用户时
> 根本无处可切**，于是这个用户永远删不掉。
>
> 而 `workflows/job-reset.md` 恰恰把这条路当作推荐做法写给用户：「要连这些一起清掉，
> 最干净的做法是删掉整个 `users/<你的用户名>/` 再跑 `/job-setup`（或用 `/job-user` 删除该用户
> 后重建）」。**用户照着 `/job-reset` 的建议来，撞上 `/job-user` 的拒绝**——而单用户正是绝大
> 多数人的情形。两份文档互相矛盾，且没有任何测试覆盖到。

## 规则
1. `<名>` 清洗掉 `/ \ : * ? " < > |`、**换行与其它控制字符**，以及首尾空白/点；
   为空则拒绝、请重取。（换行必须清——规则 2 要求 `.active_user` 是单行。
   **实测**：正本读取器是 `_cli.pick_user`，它走的是 `read_text().strip()` ——
   只削首尾空白、**不按行切**，所以带内部换行的文件会原样读成
   `'张三\n李四'` 这样一整串，`users/` 下当然没有这个目录。
   好在它**当场就说人话**：「`.active_user` 指向「张三\n李四」，但
   `users/张三\n李四/` 不存在 —— 跑 `/job-user` 看看有哪些用户」，退出码 1。）
2. `.active_user` 只写清洗后的原样标识串（可含中文），单行。
3. 只动 `.active_user` 与 `users/<名>/`；绝不碰别的用户的数据或共享框架文件。
4. 删除是不可逆的——没有确切确认不执行。
